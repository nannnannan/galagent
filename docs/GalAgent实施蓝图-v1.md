## 1. 实施规则

每阶段保持输入、写入范围与退出条件；满足后更新 NEXT。用户新增授权并发代理，允许独立模块同时开发，但阶段门必须各自有证据，不能因为后阶段代码已写而跳过前置验证。没有证据的项目写待验证，不用“代码写好了”替代验收。

当前用户已授权完成首版、项目内必要开发依赖、模型资产、生图制作和子代理协作；额度不限制仅指本轮生图。额度确实不足时允许使用重置卡，仍需工具当时的适用条件成立。API 接入使用用户提供或当前环境中的合法凭据；不从其他项目偷偷获取 token。系统保护修改、外部发布不在本轮范围。常规修复不反复询问已授权范围。

`runtime/`、测试、构建与运行包已存在；早期拟建路径不等于现有实现目录。当前模块为runtime/main、core、renderer、shared、desktop和workers；真实进度统一查NEXT。源文件与用户数据分开：代码进入 `runtime/`，用户存档放 `app.getPath('userData')` 内，运行时不写项目源树。

旧规划和素材保留历史副本；本次明确授权同步现行文档，先备份原版本。开始任何未来实现前建立可恢复基线，缺Git时保留文件备份。不要读取其他项目凭据或自动复用旧软件内部 token。

## 2. P0 · 验证决定能否开工的少数能力

预计 2–4 个有效开发日。此阶段不搭完整产品。

输入：用户确认首版；可用 Kimi API 接入，或明确记录缺失；一张通过验收的透明测试立绘。正式生图和下载权重应在获得相应授权后开展。

范围：拟建 `runtime/probes/`、测试数据和能力记录；必要最小依赖清单。不做权限模式、插件架构或任务执行器。

| 探针 | 必须输出 | 退出条件 / 失败处理 |
|---|---|---|
| Kimi 对话 | 实际可用 model ID、结构输出结果、30 次短中文响应的延迟 / 用量、失败与取消记录 | 账户可调用，输出可校验；失败就停模型接入，不能换后端冒充 |
| 桌面壳 | 透明小窗、普通输入窗、焦点与穿透演示 | 中文 IME、拖动、点角色、点空白、置顶组合通过；透明窗失败可提交普通窗降级 |
| Windows 观察 | 固定助手提供应用名、空闲、时钟 / 会话状态 | 不要管理员权限，不记输入内容，不循环启动助手；未知状态有明确定义 |
| SQLite 打包 | 应用进程建库、事务、FTS 与重新打开 | 本机开发及实际打包环境都可用；Electron native ABI 问题需先解决 |
| 语义检索 | 小型 e5 候选在本机运行、中文同义检索样本、模型来源和版本、内存 / 冷启动 | 能打包且不超预算；否则提交替代模型 / 范围提案，不删掉检索门 |
| 美术母版 | 实际透明通道、边缘、锚点、缩小显示截图 | 非设定排版图；人物轮廓、母题与桌面尺寸清晰可用 |

真实窗口场景至少包括：浏览器、文本编辑器、中文输入、最大化窗口、全屏播放器；有第二块屏幕时测混合 DPI 与拔插，没有时记录缺口。暂不测试对这些程序内容的理解。

退出：所有首版前置项通过，或用户明确接受列明限制的降级合同。输出 `docs/evidence/P0-能力验证.md`。依赖没齐时仍可做互不依赖的壳 / 存储探针，不越过缺失账户或授权做调用。

预计 3–5 个有效开发日。

输入：P0 通过；第一组透明差分可用；人格内核与首启状态合同冻结。

范围：`runtime/shell/`、`runtime/persona/`、`runtime/identity/`、`runtime/provider/` 和最小配置入口。API 密钥由主进程保护，不能进 renderer 或日志。

交付：桌面人物、普通对话窗、设置 / 退出入口、一次性首启、自取名字、固定身份记录、S2 日常状态、六表情中已验收资产、基础请求取消与失败状态。

最低检查：

- 第一次打开 → 介绍 → 她取名 → 完成；第二次打开不再问初遇问题。
- 首启每一步异常退出后能恢复，名字与游标不会半写；显示名中的中文与特殊字符不变成路径。
- 中文输入不丢字；打开 / 关闭对话行为明确；角色演出不夺焦点。
- 网络失败、格式错误、取消时不存成已完成回答，晚返回动作不执行。
- 模型输出中的 HTML / 脚本当作普通文本；枚举外动作拒绝。
- 人工用普通交流、赞美、不同意见、边界要求四种场景评审，不以模板傲娇次数计分。

退出：可以相处十分钟并可靠重开；首启和模型失败路径通过。输出 P1 记录。此时只是人物可运行，不宣称长期记忆完成。

## 4. P2 · 她记住真实相处，也能改正误会

预计 4–7 个有效开发日。

输入：P1 的完整消息事件与唯一 ID；P0 检索候选；存档事务与模型返回协议。

范围：`runtime/storage/`、`runtime/memory/`、`runtime/relationship/`、记忆管理界面；不扩大桌面读取范围。

交付：分型事实 / 相处事件 / 感受与日记；中文 FTS、实体与语义融合；生效时间与来源；去重、纠正、删除传播、导出与恢复；长期关系和短期心情分离。

固定质量样本：至少 20 条真实或人工编写的中文事实；40 条查询，其中包含同义问法、日期区别、事实纠正、未知问题、人物感受与事实混淆。测试集在调检索前固定，开发样本与最终验收样本分开。

退出指标（目标，尚未测得）：

- 有答案的验收查询中，正确来源进入 top-5 的比例至少 90%；不能只看返回文字“很像”。
- 当前事实纠正、删除后不再被当前查询使用；历史查询能区分当时与现在。
- 无证据的睡眠时间、视线或过去 coding 项目，不生成确定事实。
- 连续三次关闭 / 重开后身份与已完成会话完整；重复抽取不重复记忆。
- 1 万条压力样本报告热检索 p95、冷加载与资源开销，满足总设计案预算或提交明确调整。
- 删除派生索引与摘要经过检查；恢复备份不偷偷复活已删记忆。

退出：她换一种问法仍能记得一件事，接受一次事实纠正，并在重启后继续。输出 `docs/evidence/P2-记忆验收.md`，明确统计口径与未通过项。

## 5. P3 · 桌面相处、主动念头与微事件

2026-10-10主动扩展仅计划，承接总设计案6.1。顺序：任务完成/失败→角色判断汇报；可靠事件/环境变化；模型提出关注时间/条件；明确委托的持续目标。沿用现有OpenAI兼容API和GalAgent执行器/并行架构，不建立内置反代。

未来验收：事件ID去重；失败不报成功；安静、锁屏、休眠、取消能抑制表达并丢弃过期结果；恢复后不过量补发；无相关事件可保持安静且不执行工具；显式持续任务按委托范围运行；重启去重；记录实际API次数、预算、延迟、人物口吻和证据引用。观察关闭时可接收明确任务结果，但不恢复环境采集。自行关注时间表的持久化/重启/错过合并另行验收，不把现有运行期7天Cron当永久后台生命。

本轮不实施上述行为；Live2D、浏览器扩展、目录硬隔离与真实键鼠控制保持原停止点。

预计 4–6 个有效开发日。

输入：P2 的可追溯记忆；三类观察；六类微事件与动作目录；姿态锚点稳定。

范围：`runtime/observation/`、`runtime/initiative/`、`runtime/scenes/` 和有限 `runtime/shell/` 演出。不增加截图、剪贴板、历史、UIA 或 workspace 内容监听。

交付：E01–E06 场景状态与资格、本地事件合并、主动请求抢占、冷却与预算、可关闭的吃醋、少量涂鸦 / 位移 / 装饰光标轨迹、短期日记、小目标延续。

检查：使用可控制的时钟与事件回放验证，而不是靠等一个随机下午证明全部通过。

- 切换窗口只更新状态，不每次搭话；可疑标题不造成确定事实。
- 任意键鼠活跃按忙碌处理，不宣称测到打字速度。
- “安静”当下生效，已经在网络中的主动响应返回后被丢弃。
- 锁屏、全屏、休眠和观察暂停停止主动调用；恢复后不补发过期念头。
- 反复拖动不刷长期关系；拒绝互动与关闭观察不扣关系。
- 每种演出均有开始、结束、取消；收回后没有透明窗挡住其他应用。
- 事实不足、窗口助手退出或状态过期时能保持未知，助手故障不会持续重启风暴。

退出：用户能主动触发一类桌面互动，看到一次有来由的自主回应，也能使她马上安静。六类微事件至少各有一个回放或真实演示证据，交互质量需人工确认。

## 6. P4 · 打包、长时间运行与用户验收

预计 3–5 个有效开发日，另需至少 48 小时观察。

范围：打包配置、存档恢复、托盘、资源收回、针对失败证据的局部修复。不新增产品方向。

交付：双击运行的 Windows 包、使用与恢复说明、首版验收记录。开机自启只提供显式可选设置，不默认修改系统启动项。首版可个人本地使用；公开签名、发行渠道和分发不在此阶段默认范围。

测试组合：日常办公、中文输入、断网与恢复、锁屏 / 休眠、窗口关闭与重新打开、退出时后台作业、断电式中止模拟、窗口移出屏幕的恢复。不要为了压测停止用户正在运行的其他大型任务。

最终验收表：

| 项目 | 用户能完成的动作 | 证据责任 |
|---|---|---|
| 相遇 | 第一次启动，听见她开口并自行取名 | 真实包运行 + 用户体验 |
| 连续性 | 退出重开，身份、摆放与会话继续 | 自动化状态检查 + 真实运行 |
| 记忆 | 换一种问法问回偏好或经历 | 固定检索样本 + 用户会话 |
| 纠正 | 改正一件事，再确认她使用新事实 | 来源 / 时间检查 + 实际对话 |
| 存在感 | 拖动、点击、看到合适的表情与主动反应 | 窗口行为 + 用户判断 |
| 分寸 | 要求安静，观察她立即收回 | 取消 / 冷却测试 + 实际演示 |
| 失败恢复 | 断网重试、恢复一次存档备份 | 故障记录 + 使用说明 |
| 资源 | 保持打开而不明显拖累电脑 | 所有项目进程汇总测量 |
| 人物质量 | 至少三次相处：普通闲聊、次日再见、误会修复 | 用户判断，自动化不能代替 |

离线测试检查状态和边界；模型调用检查后端表现；真实宿主检查窗口、IME 和生命周期；用户验收检查“愿不愿继续相处”。四类证据分开。

最后做一次用户明确提出的体验调整，在同一范围中再次试用。完成后停在首版验收，不自动接入任务执行器。

## 7. 排期、止损与续接

### 下一版后端与前端增量（2026-10-18，已全部实现并验收）

总设计案6.2/6.3/9.3/9.4补充用户最新要求。后端已串起持久事件与关注列表、独立K3注意力判断、预约/条件唤醒和主角色结果回传；共享并发上限按用户说明实现20路优先级池（`RequestPool`）。已纳入浏览器观察（`BrowserPerception` + Edge MV3 扩展 + Native Messaging 本地桥接）、在线/离线/异常退出事件（`online-recovery`、`crash-reunion`）、窗口标题变更事件和明确的持久关注事项（Watchlist）。提示仅保留统一人物、能力、必要状态与执行协议，人物反应交给模型。

独立能力验收已完成：
- **禁止访问的文件夹（总设计案 9.3）**：支持默认全访问（`full-access`）与配置多条禁止路径（`directory-guarded`），通过 `realpathSync.native` 祖先链解析与 NTFS `(dev, ino)` 硬链接核对，拦截相对路径穿越、符号链接/目录联接（Junction）、硬链接别名及命令工作目录/命令字符串越界；权限变更时递增 `policyVersion` 并立即中止旧权限版本下的在途任务。
- **Kimi 原生多模态与视频输入（总设计案 9.4）**：对齐 Kimi Code 0.29.2 原生协议，支持 8 种视频格式（上限 100MB），优先走 `/v1/files`（`purpose="video"`）生成 `ms://<file_id>` `video_url`，无上传通道时自动回退至 `data:video/<ext>;base64,...` 内联 `video_url`，通过 `role: "tool"` 消息的 `keep_parts` 多模态数组发送。
- **前端面板**：结合专属 Live2D（`LD4`）提供透明人物、短输入、任务/关注事项、浏览器感知状态与禁止目录设置面板。

### 浏览器扩展增量（2026-10-18，已实现并验收）

目标按Edge/Chromium，范围承接总设计案9.1，已落地于 `runtime/desktop/browser.ts`、`extensions/edge-companion/` 与 `scripts/register-edge-companion.mjs`：

1. **浏览器桥接**：提供 MV3 扩展（`manifest.json`、`background.js`、`content.js`）、Native Messaging 主机（`native-host.mjs`）与一键注册脚本（`scripts/register-edge-companion.mjs`），通过本地 `browser-bridge.json` 桥接与 IPC `browser.report` 投递观察快照。
2. **四类元数据**：活动地址（`activeTab`）、打开标签（`openTabs`）、按时间/关键词检索的历史查询（`queryHistory()`）、收藏夹列表与增量变化（`bookmarks` / `bookmarkChange`）。
3. **注意力接入**：浏览器事件送独立K3判断，支持保持安静、稍后关注与唤醒主角色；主会话串行，重复事件合并，完成/取消后旧结果不重新触发。
4. **网页正文**：作为单独能力接入真实页面内容（`pageContent`）；导航/切页后旧正文立即失效，网页内容只作观察数据、不会直接启动任务，收藏、历史与后台标签不能冒充当前正文，且遵守 `captureBlocklist` 黑名单过滤。

P0–P4、DC1–DC6、LD0–LD4 及第 7 节增量现已全部实现并通过单元与打包端到端验收；最新交付细节统一记在 [NEXT](../NEXT.md) 与 [CHANGELOG](../CHANGELOG.md)。

### 绑定和表达要求

- 参数族：头部三轴（`ParamAngleX/Y/Z`）、身体三轴（`ParamBodyAngleX/Y/Z`）、眼球 XY（`ParamEyeBallX/Y`）、左右眼开合与笑眼（`ParamEyeLOpen/ROpen/LSmile/RSmile`）、左右眉高低与角度（`ParamBrowLY/RY/LAngle/RAngle`）、嘴开合与嘴形（`ParamMouthOpenY/Form`）、脸颊红晕（`ParamCheek`）、呼吸（`ParamBreath`）及前发/侧发/后发三组物理摆（`ParamHairFront/Side/Back`）。
- 动作优先级：明确用户交互 > 有来源事件/表达 > 当前情绪 > idle。状态快照不反复重播动作；有开始、结束、取消和回到idle的路径。
- 视觉质量红线：严格遵守 [AGENTS.md](../AGENTS.md) 第 4 节记录的 6 条防回归约束（面部垂直中心轴 `x = 500.2`、2x 超采样手绘虹膜与无白框眼窝、闭眼 `︶` 与笑眼 `︵` 弧度区分、张口 `mouth-closed` 隐藏去阴影、转头侧发 `y <= 204` 锁死防腮红穿帮、后发 `ma > 0` 轮廓门控防深色桌面壁纸白边）。

### 运行时边界

只更换人物渲染适配，不重写core/SQLite/后台任务。保留现有视觉语义、鼠标坐标输入、焦点、透明窗、拖动位置、记忆管理和可选长聊入口。模型文件缺失/不兼容/损坏时保持可操作并自动回退二维WebGL形体，不清空数据，不自动打开固定页面掩盖失败。
