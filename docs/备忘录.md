## Gmail（MCP）· 2026-11-04 · 暂缓

用户原话：“先把 MCP Gmail 往后推吧，写进备忘录。这个涉及安全，我还要再想想。”

- **可行性**：谷歌对个人开放 Gmail API（OAuth）。
  - 个人自用：在自己的 Google Cloud 项目里建「桌面应用」OAuth 客户端，把自己加为测试用户，不用谷歌审核。
  - 「测试」状态下授权大约 7 天要重新登录一次（以谷歌文档为准）。
  - 公开发布要过受限权限审核和安全评估，不现实。
- **现成 MCP**（2026-11-04 在 npm / PyPI 核对）：
  - `@gongrzhe/server-gmail-autoauth-mcp` 1.1.11（ISC）
  - `@shinzolabs/gmail-mcp` 1.7.4（MIT）
  - `workspace-mcp` 2.3.0（PyPI，Gmail + 日历 + 云盘 + 文档）
  - 谷歌官方 Gmail MCP 未核实。
- **如果做，建议的安全边界**：
  - 默认只读权限；
  - 进主动研究时只看发件人和主题这一层（订阅了什么、快递、行程），不读正文、不存原文，发给模型前照样脱敏；
  - 加一个默认关闭、只有用户能开的「邮件」渠道开关，AI 改不了；
  - 发信权限默认不给；要给的话，每封都走编号确认（和运行命令一样）；
  - 国内需要代理才能访问 Gmail 接口。
- **形式**：做成「连接」页的 MCP 模板（锁版本号），和 Google 日历模板同样用 OAuth 凭据文件路径。
