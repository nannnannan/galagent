# 像素小人方案调研

> 2026-10-29 · 目的：替换 Kimi Live2D，改为可选择、可自制的像素桌宠。只调研思路，不引入第三方美术素材。

## 参考项目

| 项目 | 要点 | 许可 |
| --- | --- | --- |
| [tonybaloney/vscode-pets](https://github.com/tonybaloney/vscode-pets) | VS Code 侧栏宠物，20 多种角色。用**状态类**组织行为（`sitIdle / walkLeft / runRight / lie / climbWallLeft / jumpDownLeft / land / swipe / chase …`），每个状态的 `nextFrame()` 返回“继续 / 完成 / 取消”，静态状态按 `holdTime` 帧数结束，由宠物类选择下一个状态。素材是每状态一张 GIF，宠物“朝向”靠水平镜像。 | 代码 MIT；美术来自多位作者（itch.io 等），**各自授权**，不可直接拷贝 |
| [Shimeji-ee](https://github.com/TigerHix/shimeji-ee/blob/master/readme.txt) | 经典桌面小人。`actions.xml` 定义动作（Pose 图片 + 锚点 + 速度 + 时长），`behaviors.xml` 按条件（是否在地面 / 窗口边缘）和频率选择行为；**拖拽 Dragged、下落 Fall、被抛 Thrown、追鼠标 ChaseMouse 为必备行为**。每帧一张约 128×128 PNG，默认朝左、镜像得到朝右。 | 程序 BSD 风格；角色图多为同人，不可复用 |

| [ardakalper/pixel-pet](https://github.com/ardakalper/pixel-pet) | Electron 透明全屏置顶窗，只有指针在宠物身上时才接收点击（其余点击穿透）；内置像素编辑器，导出 Aseprite 风格精灵表 JSON。 | 见仓库 |

## 结论与取舍

1. **数据而非代码**：采用 Pixelie 式“调色板 + 字符网格” JSON，人和 AI 都能直接写、能 diff、能严格校验；比 PNG 精灵表更适合“玩家 / Agent 自制”。
2. **分层推导代替逐帧手绘**：vscode-pets / Shimeji 每个动作都要整套帧，制作成本高。我们拆成 底图 + 眼睛（按表情）+ 嘴（开 / 合 / 笑 / 噘）+ 腮红 + 腿（走路帧）+ 附件（耳朵 / 尾巴摆动帧），表情 × 动作由组合得到；缺失的闭眼 / 笑眼 / 晕眩眼自动推导。仍保留可选的 `frames` 整帧覆盖给高级作者。
3. **动作 = 程序化姿态**：位移、挤压拉伸、倾斜、跳跃用弹簧在渲染时叠加（像素本身保持锐利），因此 32×32 也能做出顺滑的动作；朝向沿用镜像。
4. **必备交互**参考 Shimeji：拖拽晃荡、落地挤压、甩动后晕眩、点击反馈。
5. **尺寸**：主流像素桌宠 16–64 px；我们以 32×32 为基准（Q 版大头、大眼、1px 深色描边、2–3 级明暗），允许 16–64。
6. **生成方式**借鉴 pixel-sprite-generator：内置角色由参数化配方（椭圆 / 矩形图元 → 自动描边 → 阴影 / 高光 → 对称镜像）生成，保证风格统一、左右对称。
7. **许可**：所有内置像素图均为本项目原创（`scripts/pixel-pet/generate-builtins.mjs` 生成），未复制任何第三方美术。
