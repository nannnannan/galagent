# 记忆系统 v2 · 每日档案 + 原文召回 + 遗忘曲线

> 2026-10-29。目标：日记改为每个自然日零点整理一次；次日对话里，前一天以“档案摘要”代替原文进入上下文，完整原文仍保存在本地，可随时召回。

## 参考的开源项目

| 项目 | 借鉴点 |
| --- | --- |
| [MemoryBank / SiliconFriend](https://github.com/zhongwanjun/MemoryBank-SiliconFriend)（[论文](https://arxiv.org/abs/2305.10250)） | 按天生成事件摘要（daily event summary）+ 全局用户画像（global portrait）；仿艾宾浩斯遗忘曲线 R=e^(-t/S)，被回忆时强化 S |
| [Letta（原 MemGPT）](https://github.com/letta-ai/letta) | 分层记忆：上下文只放摘要，完整历史留在 recall memory，由模型通过工具检索（recall_memory_search） |
| [mem0](https://github.com/mem0ai/mem0) | 事实的 ADD / UPDATE / DELETE / NOOP 操作（v1 已采用，保留） |

## 设计

1. **每日档案（`runtime/core/daily.ts`）**：每次 tick 每分钟最多扫描一次；本地日期已经结束、近 14 天内、有对话却没有“有效档案”的日子，会以 `work:daily:<日期>` 入队。作业 id 按日期唯一，所以重启、重复扫描、连点「重新整理」都不会重复生成。一次请求同时产出：客观摘要、话题、高光、待续话题、角色的第一人称日记，以及更新后的用户画像。
2. **上下文替换**：今天的消息、跨午夜最近 2 小时内的消息、以及档案尚未生成（或失败）的日子按原文进入上下文；其余日子只以 `dailyArchives`（最近 3 天）+ `userPortrait` 出现。原始私有协议记录（transport）遵循同一规则。
3. **原文不丢**：所有消息仍在本地 SQLite；主角色可用 `recall_day` 工具读取某天的完整原话（可加关键词过滤，结果有长度上限）。
4. **一致性与防误操作**
   - 档案记录覆盖消息的指纹（`dayDigest`）；删除或纠正当天任何消息后指纹变化，档案在读取时立即失效、下一次扫描删除并重建，被删内容不会留在上下文里。
   - 只整理“已经过去”的日子；时钟回拨不会整理未来；整理过程中当天记录变化会延迟重试。
   - 失败沿用作业重试（指数退避、最多 3 次），失败日期在「札记」页显示并可手动重试。
   - 「重新整理」：排队或运行中再次点击无效；同一天整理完成 1 分钟内拒绝重复；今天不能提前整理。
   - 存档导出 / 导入包含档案、画像、成就；导入的档案在读取时按指纹重新校验。
5. **遗忘曲线**：事实记忆被角色实际引用（`sourceIds`）时 `recalls+1`、刷新 `lastRecalledAt`（每天最多一次，防刷）；检索加权按 e^(-t/S)，S = 30 天 ×(1+recalls)。

旧的“每 10 次互动写一篇日记”已停用；历史日记保留。
