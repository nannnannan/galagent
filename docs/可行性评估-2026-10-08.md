# GalAgent 可行性评估

日期：2026-10-08（Asia/Shanghai）  
对象：当前项目的规划与资产；模式：只读架构评估，另行交付新版规划。  
结论：**“有持续人格、能记住相处、会主动回应桌面变化”的第一版可行；旧 M1 的范围与若干保证需要重设。**

本轮用户明确选择：**先把人物、记忆和桌面互动做活**。真实任务执行后移，不从长期产品方向中删除。本报告中的实现建议仍是提案，不代表已经实现或验收。

|---|---|---|
| 代码 | 无运行代码、依赖清单、构建脚本、测试或 `runtime/` | 目前处于设计阶段，不能评价实际执行可靠性 |

## 2. 可行性分层

| 目标 | 判断 | 实现条件与边界 |
|---|---|---|
| 首启自取名、跨重启持续身份 | 可行，工程难度较低 | 原子保存身份；崩溃恢复；名字不作为文件路径 |
| 有变化的角色对话与表情 | 可行，体验质量需实测 | 统一差分、受约束的动作输出、人工角色评审 |
| 可靠长期记忆 | 可行，工程难度中等 | 区分事实与感受；检索、纠正、删除和未知答案测试 |
| 前台应用、空闲、时间感知 | 可行，需本机验证 | 少量 Win32 观察；观察失败时明确不知道 |
| 主动搭话、吃醋、桌面小动作 | 可行，体验难度中等 | 同一事件去重、冷却、忙碌抑制、即时收回 |
| 全系统语义理解 | 不能承诺普遍可靠 | UIA 覆盖、权限、窗口内容、截图读图都存在缺口 |
| 真正执行 coding / GUI 任务 | 另一期可做 | 单独验证执行器与授权边界；不靠陪伴壳间接保证 |
| 全权限自动行动且可靠回滚 | 旧保证不成立 | 原生进程隔离、外部副作用、恢复范围必须重新定义 |

最大的未知是**相处一小时后是否仍像一个人物，并且让你愿意继续开着她**。继续增加感知源，不能自动解决这个问题。

## 3. 需要先修正的设计合同

以下 P1 / P2 是规划风险等级，不是声称当前程序存在漏洞。当前尚无程序。

### F01 · P1：多个文件同时自称唯一权威，且引用不存在的版本

证据：旧交接总览第 4–7 行自称现状权威；旧计划书第 6 行自称唯一设计输入；交接第 127 行又将人设放在所有设计之上。旧开工卡第 5、7 行及旧感官架构第 5 行引用不存在的 `GalAgent计划书-v0.4.md` / `v0.5.md` 和 `人设总册-v1.1.md`。

后果：接手者可以从同一目录读出不同范围，连文档链接也无法追踪。交接第 138 行建议用口头确认替代版本纪律，会使这个问题继续积累。

纠正：新版只设“总设计案 → 实施蓝图 → NEXT”的职责链。旧文件保留作历史材料；新版经用户确认后再生效。文档内容修订号与文件名分开，引用稳定物理路径。验收：三个新入口互链可打开、只有 NEXT 记录当前进度、实际阶段边界一致。

### F02 · P1：旧 M1 宣称 T0–T2，却没有完整的 T2 执行闭环

证据：旧开工卡第 13 行承诺 T0–T2；第 15 行排除执行编排和 Computer Use；十项任务中也没有“用户提出任务 → 工作区写入 → 校验 → 恢复”的交付。旧计划书第 254 行的 M1 还是叙事 GDD，和新开工卡第 13 行不同。

后果：可能完成大量陪伴功能，仍无法判定 T2 是否交付。旧开工卡第 36 行要求主动发现工作区错误，而文件变动并不能证明错误。

纠正：按照本轮用户选择，第一版明确为陪伴版本，不承诺真实任务执行。未来执行阶段单独交付一项可复现的小任务。禁止把“看见文件变化”写成“理解代码错误”。

### F03 · P1：完全访问模式与“永远不可越过”的红线相互矛盾

证据：旧计划书第 165 行要求红线在 L1；第 173 行完全访问模式关闭全部闸门；交接第 86 行又要求永远不可读取私钥或改写 broker。

后果：关掉强制层后，无法同时保证这些规则仍强制生效。模型的“高置信度”也不等于动作已获授权。

纠正：第一版不提供执行权限模式。以后将不可修改的能力边界、会话授权和模型建议分开；Jev 可以辅助判断，不发放权限。对“完全访问”的最终语义另行评审。

### F04 · P1：同一用户下的子进程与虚拟桌面不能证明沙箱隔离

证据：旧计划书第 212 行称“沙箱子进程执行”；旧感官架构第 100 行将 Hyper-V、Win+Tab 虚拟桌面、WSLg 混为可保证不触碰宿主的副桌面。

后果：窗口分组不是文件或网络隔离；任意 shell 和外部 agent 也不一定经过本项目的 broker。列出路径黑名单不等于限制了进程权限。

纠正：执行阶段必须说明采用哪种实际隔离，以及宿主挂载、网络、凭据和退出后的状态。不把同账号子进程叫安全沙箱。当前只启动固定观察助手，不向模型暴露命令执行。

### F05 · P1：九项感知被写成“原生、免费、全系统可用”，缺少逐项证据

证据：旧感官表第 33–41 行；第 53 行又写核心八项，循环第 112–121 行加入了工作区文件变化、漏掉了另一套列表中的时钟。UIA、浏览器历史、进程命令行、剪贴板的访问与隐私成本不同。

后果：既无稳定清单，也把 API 存在当成应用内容可读。微软文档明确 UIA 的跨完整性级别访问限制，见下方来源。

纠正：第一版只做前台应用、输入空闲、时间与会话状态三类观察。标题只在用户开启后使用，不采集窗口正文或输入内容。其余观察逐项进入后续能力门。

### F06 · P1：记忆系统会把推测、日记和真实事实混在一起

证据：旧计划书第 78–80 行将生成事实与对话事实放进同形追加接口，未定义来源、冲突和删除传播；旧开工卡第 25 行用“他骂了我”回答“今天运气好吗”作为检索验收；第 40 行要求知道昨晚几点睡。

后果：语义相关不等于答案正确。日记的情绪描写会变成“发生过的事实”；离开电脑也不能证明入睡。

纠正：分别保存用户明确陈述、可验证观察、角色感受。每条事实能追溯到来源，修改有生效时间，删除连同索引和派生摘要处理。没有睡眠证据就回答不知道。

### F07 · P1：先把敏感内容交给模型，再识别遮挡，不能保证未外发

证据：旧感官第 81 行允许“敏感关键字如果被 VLM 识别”后马赛克；第 20 行又要求像素永不进入任何人的上下文。VLM 要读图，就必须收到像素。截图“24h 后删”与“取消 24h 例外”也有冲突。

纠正：第一版不截图、不监视剪贴板、不读 IM 内容。未来读图明确区分主对话与临时视觉处理器，外发前本地选择范围与脱敏；不声称摘要能消灭隐私风险。

### F08 · P2：PNG 插画不等于可以运行的桌面形体

证据：本轮透明度检查结果；根目录设定图包含排版、文字和多表情分区。旧计划书第 103 行直接设想 Live2D / 序列帧，未提供模型或统一动作资源。

纠正：先生产同画布、同锚点的一组透明 PNG 差分，用有限的位移和缩放表达动作。首版不依赖 Live2D 绑定。现有插画用于风格参考、相册或后续回忆卡；统一差分与透明边缘仍需人工验收。

### F09 · P2：旧主动性公式没有足够的打扰与成本约束

证据：旧感官第 149 行公式随离上次开口时间增长；第 156 行微动作不限；旧人设第 181 行要求每分钟酝酿萌点；旧开工卡第 38 行要求切到其他 AI 两秒内出声。

后果：切窗口会触发重复反应，忙碌与休息被误判，全天调用费用无法从规则看出。

纠正：本地筛选与合并事件，模型决定表达。主动发言有上限、冷却和再次检查；全屏、锁屏、手动安静立即取消。两秒内更新观察状态可以作为目标，是否说话不应成为强制指标。

### F10 · P2：人设的硬配额会制造模板傲娇与事实冲突

证据：旧人设第 130–131 行要求每三轮反差、每次被夸必防御；第 180 行要求每句台词和动作至少一处对不上；第 188 行声称知道视线停留 0.7 秒，但相机明确不做。S0 自动转 S2 与第 151 行的 S2 分数门槛也不一致。

纠正：保留嘴硬心软、星空 / 棱镜 / K 的核心，改为总体倾向而非句句打卡。鼠标悬停只能表示悬停，不能当作视线测量。首次会面完成直接进入 S2；长期变化靠具体相处事件，不靠刷次数。

### F11 · P2：公开介绍与基准数字不足以证明项目接入效果

证据：本轮确认 Kimi K3 和 Jev 的官方资料存在，但未调用账户；mem0 当前 README 特别说明其公布的分数来自托管平台，含开源 SDK 不具有的专有优化。旧计划书第 71、78 行却把相关成绩与自研同形接口紧邻呈现。

纠正：借鉴记忆分层与检索思想，不宣称自研实现继承公开成绩。先测试本项目中文记忆样本与设备开销，Jev 接入后置。生图型号、生成质量和费用也不沿用未经本轮验证的历史保证。

### F12 · P2：影子快照无法普遍撤销进程和外部副作用

证据：旧计划书第 176–179、221–222 行以目录副本承诺“回到十分钟前”，但同时允许进程 spawn 和出站请求。

纠正：未来恢复合同列出可恢复文件、数据库状态、不可撤销的网络行为和用户并发编辑冲突。首版恢复仅针对自己的存档备份，不包装成整机回滚。

## 5. 首版建议与代价

保留：她自行取名；简短初遇后进入拧巴期；隐藏关系状态；自然对话；跨重启记忆；主动念头；有限的吃醋与胡闹；用户能让她安静。

首版收束为：**一人、一台 Windows 电脑、一个 Kimi 对话后端、一套统一差分、三类观察、一个本地数据库、六类微事件。**

建议按 16–27 个有效开发日规划，再留至少 48 小时观察；通常约 3–6 周，依赖 API、透明差分和本机验证按时就绪。只是排期区间，不是交付保证。若想压到更短，应收缩微事件与美术数量，不能删去来源、暂停、重启恢复等基础能力。

## 6. 来源与验证边界

网络搜索工具本轮出现传输错误，随后直接读取官方网页。没有调用付费推理、生图或 Jev API，没有下载模型权重、安装依赖或改系统配置。

- [Kimi 开放平台](https://platform.moonshot.cn/docs)：本轮页面列出 `kimi-k3`、流式与 JSON Mode，K3 推理强度默认值与低档选项。实际账户权限及响应速度未知。
- [TypeSafe AI Introduction](https://docs.typesafe.ai/introduction)：Choice / Score / Noul 等类型化判定；只能证明官方接口概念，不能证明本项目的授权正确性。
- [Electron 透明窗口](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)：透明区域不能自动获得点击穿透，且有窗口限制。
- [Electron 自定义交互](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)：`setIgnoreMouseEvents` 及鼠标移动转发；组合行为需要本机验证。
- [Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)：renderer 隔离、限制 Node 能力、IPC 校验等工程约束。
- [GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo)：会话内最后输入时间，不是打字速度、全系统活动或睡眠证明。
- [UI Automation 权限说明](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview)：不能保证普通进程跨越完整性级别观察所有程序。
- [mem0 官方仓库](https://github.com/mem0ai/mem0)：检索策略可参考；托管平台成绩不能移植为自研成绩。
- [multilingual-e5-small 原模型](https://huggingface.co/intfloat/multilingual-e5-small) 与 [Transformers.js 版本](https://huggingface.co/Xenova/multilingual-e5-small)：拟用作本地语义检索候选；前缀与归一化规则按原模型说明实现，尚未验证打包、内存或中文召回。

未解决项：没有代码与真实宿主运行证据；没有模型账户调用证据；没有可用透明差分；没有性能基线；没有用户实际体验验收。详细实现边界见 [总设计案](GalAgent总设计案-v1.md)，阶段门见 [实施蓝图](GalAgent实施蓝图-v1.md)。
