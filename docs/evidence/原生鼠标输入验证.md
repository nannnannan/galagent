# 原生鼠标输入验证

2026-10-09。实际 Windows 输入，针对本项目打包的 `GalAgent.exe`；不是仅向 renderer 分发合成 DOM 事件。

初版只依赖 Electron forwarding / DOM mouseleave 切换穿透。实际菜单 hover 后，Windows `WS_EX_TRANSPARENT` 仍为 true，Computer Use 的输入目标检查会识别到下层窗口。没有向该下层窗口发送点击。两次重试失败后停止，并只读核对本应用自己的窗口样式。

修正：主进程在人物附近读取原生光标位置，发 typed hit-test 请求；renderer 用已缓存的 alpha、菜单、气泡及拖拽捕获做判断，主进程据返回值恢复 / 开启系统穿透。坐标不落盘、不送模型，仍保持 `focusable:false`，没有为了测试改成抢焦点窗口。

修正后的真实输入结果：

- 点击 30px 圆形相处按钮成功出现原生菜单。
- 从原生菜单选择「和她说话」成功打开实际普通对话窗。
- 在人物实体区域用真实鼠标拖动，窗口位置实际移动并写入自己的位置文件。

透明位置、实体、菜单气泡、旋转和平移映射、拖动释放由 alpha 单元 / UI 测试另行覆盖。这些源与实际 Windows 输入结果共同构成证据，不能只凭 DOM click 声称完整原生输入成立。

尚未模拟多显示器拔插、不同 DPI 或用户真实长期手感。没有改系统鼠标、IME、隐私或保护设置，也没有把测试动作发送到其他应用。
