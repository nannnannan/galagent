# P0：真实多语语义检索实测

结论：`Xenova/multilingual-e5-small` q8 在本机可离线运行，中文同义问法的候选召回有效；它不能判断未知问题是否有答案。首版需把检索结果作为带来源的候选材料，不以余弦阈值代替事实证据。项目全进程内存预算尚需另测。

## 可复现资产与命令

模型 revision：`761b726dd34fb83930e26aab4e9ac3899aa1fa78`。原始 ONNX 仓库：<https://huggingface.co/Xenova/multilingual-e5-small>；其 README 指向基座 `intfloat/multilingual-e5-small`，基座官方 metadata 当前标记 MIT（revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`）。本轮使用官方 Hugging Face endpoint，未使用镜像。

初次 Node 自动下载出现 `fetch failed`；同机器 PowerShell 官方 endpoint 可达，因此使用 `Invoke-WebRequest` 按固定 revision 下载，再传本地绝对路径给现有 worker。未把下载失败误报为模型能力失败。

```
.cache/models/
  model-metadata.json
  base-model-metadata.json
  Xenova/multilingual-e5-small/
    README.md
    config.json                 658 bytes
    tokenizer_config.json       443 bytes
    tokenizer.json              17,082,730 bytes
    onnx/model_quantized.onnx   118,308,185 bytes
```

4 个运行文件合计 135,392,016 bytes，约 129.12 MiB。给 `Embeddings` 的 `modelPath` 必须是上述 `Xenova/multilingual-e5-small` 完整目录，不能只给 ONNX 文件。worker 指向 `runtime/workers/embedding.mjs`，本地路径模式 `allowRemoteModels=false`。

运行：`node --import tsx scripts/probe-embedding.mjs --offline`。

固定样本在第一次模型调用前写入 `embedding-fixed-fixtures.json`：20 条人为编造中文事实（其中一条旧偏好 invalid），40 个查询（35 可回答，5 未知）。内容覆盖同义、时间、纠正、标题权限及桌面应用，没有使用真实用户私人材料。原始下载失败保存在 `embedding-live-result.json`；成功数据与每条 query 排名在 `embedding-offline-result.json`。

## 数值结果

测试于北京时间 2026-10-08 23:51 / 23:52 执行；两次独立进程加载同一固定数据，没有针对错误改变样本。

| 指标 | 第一次 | 带峰值记录的复测 |
|---|---:|---:|
| 模型进程冷加载并输出首向量 | 2,055.71 ms | 1,850.64 ms |
| 维度 | 384 | 384 |
| 35 个可答 query Top1 | 33/35，94.29% | 相同 |
| 35 个可答 query Top3 | 35/35，100% | 相同 |
| 40 query 编码均值 | 7.44 ms | 6.33 ms |
| query 编码 p95 | 8.30 ms | 7.92 ms |
| 首向量时进程 RSS | 518.65 MiB | 531.07 MiB |
| 完成时进程 RSS | 666.70 MiB | 644.88 MiB |
| 复测推理/扫描期间峰值 RSS | 未采集 | 644.88 MiB |
| 编码与合成扫描累计 CPU | 12.36 秒 | 10.44 秒 |
| 1 万向量热扫描 p95 | 22.94 ms | 23.81 ms |

RSS 和 CPU 为测试 Node 进程及其中 worker，不包括 Electron、renderer、桌面 observer。冷加载是新进程首次模型加载，文件系统缓存可能已热，不是重启后的磁盘冷启动。CPU 时间可超过墙钟时间，因为 ONNX 多线程推理。没有用这些数值宣称整项目满足 800 MiB。

热扫描将已编码的 20 个向量重复构造 1 万条，连续扫描 100 次；标签明确是 synthetic，不是 1 万份真实中文资料的索引或 end-to-end DB 查询。距离使用 query/passsage 前缀、mean pooling、normalize 后的余弦，未用字符串伪装向量。

## 错误与不能自动判答的证据

Top1 错误：`星期六下午通常做什么？` 首位误召工作时间，正确的周六游泳排第二；`他的终端工具是什么？` 首位误召应用项目，正确的 Windows / PowerShell 排第二。Top3 可以交给受约束模型进一步判断。

| 未知 query | 最高余弦 |
|---|---:|
| 他的手机号码是多少？ | 0.85083 |
| 他最喜欢哪支足球队？ | 0.82709 |
| 他今天午饭吃了什么？ | 0.85883 |
| 他的显卡型号是什么？ | 0.85024 |
| 他住在哪个街道？ | 0.81526 |

5 个未知 query 都会越过 `.65` 召回阈值。即使提高到 `.8` 也全部被召回；不能把相似度当成“已知答案”的置信度。应在 prompt 明确只引用材料确实支持的事实，材料无答案必须说明不知道，检索只给少量候选而不自动写入记忆。后续可用独立相关性判定并做未知样本验收；本轮没有以调整阈值对这 5 条过拟合。

3 个偏好纠正 query 都首位召回最新乌龙茶 f18（0.89991 / 0.90895 / 0.90128），旧冰绿茶 f20 由 `valid:false` 在排名前排除。这个结果证明过滤有效，不能证明模型自带纠正语义或应用整个迁移流程已验收。相对时间如“明天”“昨晚”仅是固定样本文本，生产环境仍需事件时间锚点。

## 后续优先项

1. 项目实进程总量与长期静置验证；若突破峰值预算，限制 ONNX 线程、worker 空闲卸载或独立进程按需启动，再复测延迟和内存。
2. 独立检索集扩充多轮事件与相对时间，实际数据库 1 万条基准；不把本轮 synthetic 扫描当规模验收。
3. 未知问题、冲突及纠正的真实模型对话验收，确认不会引用无关候选编造事实。
