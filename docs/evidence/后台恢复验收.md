# 后台工作恢复验收

2026-10-09。本轮针对已完成聊天的事实 / 札记抽取，以及已保存事实的缺失语义向量。保持人物、动作、观察范围、API 参数和增量摘要合同。

## 实现

- 成功聊天与抽取 work-job 在同一 SQLite 事务落盘。任务只保留来源 ID、类型、状态、尝试次数与下次时间，不复制聊天正文、密钥或私有推理。
- 事实、按来源配对去重的札记与完成 checkpoint 原子提交。退出保留未完成任务，重启核验来源和配对后续接；不重新抽取所有旧会话。
- 每次失败有指数退避，最多三次；终止失败在重启后的界面状态可见，明确保存连接配置可重试。未配置时不发送抽取请求。
- 启动补建缺失向量。删除移除 / 取消同源任务；纠正过的原事实片段不重新成为当前事实。恢复覆盖同 ID 的来源或记忆正文时，旧抽取 / 向量响应不提交，按新文本续接。
- 提取结构必须是非数组对象，facts 字符串数组最多3、每项2–300字符，diary 字符串最多700字符。合法但非用户原句的事实仍被过滤；错误结构进入重试，只有合法空数组与空日记能算空成功。

## 验证

38 项全项目单测及类型检查通过；其中新增 9 项恢复集成用例，包含 12 个错误结构子样本。覆盖：抽取中退出重启一次续接、配置完成恢复、三次上限与持久退避、终止失败后明确配置重试、删除取消、纠正不复活、事实 / 札记幂等、同 ID 文本改写、旧向量隔离、旧事实缺失索引补建。

所有核心测试实例显式使用 fixture fetch。既有非提取测试的后台 fixture 只修正为合法空结构，原测试目的与断言保留。独立审查发现的「错误结构被标完成」已修复并纳入测试。

实际 Windows 运行包的协议测试增加：保存一次聊天后，fixture 暂不返回后台抽取；退出应用，再以同数据目录重启；后台仅续接一次，最终事实不重复且语义索引达到 ready。最新机器结果以 `tests/e2e/evidence/protocol-result.json` 的 scope、checks 和 counts 为准。

## 边界

普通人类可读存档不迁移待处理 work-job；同一 userData 的退出重启可续接。已抽取事实随普通存档迁移，缺索引在恢复后补建。没有改变存档格式或自动重扫旧所有聊天。

真实 Kimi 账户、人物质量、锁屏 / 休眠物理切换、连续48小时及用户相处仍未验收。后台恢复不代替六微事件、心情、关系与小目标的实现；详见完成审计。
