## 0. 调研纪要（本轮新事实）

### 0.1 Jev 是什么、不是什么

用户提到的「JEV 决策模型」经核实为 **Jev** —— TypeSafe AI（旧金山，2024 年创立，创始人含 OpenAI RLHF/ChatGPT 前员工 Diogo Almeida）于 **2026-09-15** 发布的「System One 模型」。要点：

| 属性 | 内容 | 对本项目的意义 |
|---|---|---|
| 本质 | **判别式**模型，不做生成；输出带概率分布与置信度的类型化判定 | 幻觉免疫不是 slogan：它不生成字符串，输出空间预定义 |
| 接口 | `state` + 三类问题：`noul`（是非）、`choice`（无序多选）、`score`（有序分档），并行返回分布 | 恰好是"动作安全判定器"需要的接口形状 |
| 核心训练 | RLCD（按校准误差惩罚的强化/监督），主打**校准置信度**："说 95% 就真有 95% 对" | 给"判官的可信度可度量"提供了工业先例 |
| 速度 | 官方声称 70–500ms，比前沿 LLM 快 40–200 倍 | 放在每次工具调用前做闸门，延迟可承受 |
| 定位 | "LLM for chat, Jev for automation"；用例含 LLM 输出验证、越狱侦测、质量门 | 官方自己也定位为**其他模型的判官/门卫** |

**Jev 不是什么**：它没有权限模型、没有防注入承诺、没有校准失败时的兜底。它是「判断层」的一块合格积木，不是安全架构本身。即使不接 Jev API，它的接口形状（state + 是非/多选/分档 + 校准置信度）值得我们**照抄自研**——判官可以先用本地模型或现有 API 实现，Jev 作为可替换后端之一。

### 0.2 决策/门卫模型的生态位（知识沉淀，注明时间敏感性）

截至本调查时点，产业界与公开文献里和 Jev 同层或可替代/互补的方案：

- **专用门卫模型**：Llama Guard 系列、Meta Prompt Guard（注入/越狱侦测）、ShieldGemma、NVIDIA Aegis 内容安全模型——判别式/微调判别式，常被放在 agent 动作前后做过滤。它们管"内容"，不一定校准得可度量。
- **推理模型自评 / Constitutional AI**：用生成式大模型按原则清单自评输出。灵活但与被审者同源同受创面，且无法给出可校准概率。
- **进程内权限分级**：Claude Code 模式允许/询问/拒绝清单、OpenAI Operator 的确认页——**确定性规则层**，不是模型，但它是所有方案里唯一无法被提示注入绕过的层。
- **计算机使用的前沿**：UI-TARS、(计算机使用 API)、Browser Use 等把"看屏幕-动鼠标键盘"做成闭环 agent；GUI 自动化层正商品化——说明**"动手"这件事我们不需要自研到很深**。
- **轨迹审计**：AgentDojo、AgentHarm、τ-bench 一类基准衡量的是"组合动作造成的危害"，不是单步动作——确认了**单步判官必然漏组合**，审计与红队轨迹库必须要。

**结论（写进架构的）**：安全判定层必须是**多范式组合**——确定性规则引擎（哑的、不可说服） + 一个可校准判别式判官（Jev 或其自研替代） + 用户最后一道门。任何单一决策模型都不足以当"红线"。

### 0.3 美术资产盘点

| 目录 | 内容 | 与傲娇小姐定式的关系 |
|---|---|---|
| `图片素材最初版/星空公主100图/` | ~50 张 PNG + 同名 txt 提示词 + `manifest.json` + `创作方向.md` | **同一角色**：白毛/傲娇/白裤袜/星空披肩，人物系环境插画风，非 sexy |
| `图片素材最初版/Kimi娘50张-画风探索/` | 50 张 Kimi 娘画风探索（水手裙、水彩、彩铅、像素等），PNG + txt | **画风探索期产物**：同一人物的不同服装/氛围试验 |

新收到的「傲娇小姐设定卡」（`mirasim-att` 墙纸参考图）是我们见过的**最完整的定式表**：主立绘、五组表情差分（生气/傲娇/害羞/惊讶/意外单纯）、三枚 Q 版、五处服装细节、性格关键词。**它将作为 GDD 的附录 A 正式入档。**

### 0.4 GPT 图像额度（gpt-image-2.5）

用户授权：可以调用本机已有的 OpenAI/GPT 额度生成立绘，**暂不设上限**。落地约束：

- **写入白名单**：所有生成的图一律只写入 `galagent/图片素材最初版/**` 或 `galagent/runtime/assets/generated/**`，绝不散到别处。
- **可复现**：每张图落盘时必须带 `.txt` 提示词档案（沿用现有目录约定）+ 一行 manifest 记录（时间、模型、种子如有、target 槽位）。
- **用量台账**：尽管"不限额度"，后台幂等脚本每记一笔调用，出一个 `image-ledger.json`——日后要审计成本由来已久，拖不得。
- **先补差分后补剧情**：生图优先级 = GDD 确定的"需要复用的动作/表情槽位" > 剧情 CG > 单纯好看的散图。
- **透明底直出**：gpt-image-2.5 已支持透明背景输出，差分立绘直接叠在桌面透明窗上，**抠图管线整个省掉**；验收时改为检查边缘留白、半透明残留和阴影方向一致性。

### 0.5 记忆系统调研纪要（GitHub，2026-10-08）

用户提出两点：不能只有日记日志；去 GitHub 找成熟可复用的长期记忆方案。调研结果如下（star 量为调研时点数据）：

| 仓库 | 亮点 | 对本项目的用途 |
|---|---|---|
| **mem0ai/mem0** ⭐~67k · Apache-2.0 · Python/JS | 2026 新算法：单遍 ADD-only 记忆抽取（不做 UPDATE/DELETE）、agent 生成事实与对话事实同等权重、**实体抽取+跨记忆链接**、**多信号并行检索（语义 + BM25 关键词 + 实体匹配）融合打分**、时序推理；LoCoMo 92.5 / LongMemEval 94.4；一句 API `add()` + `search()` | **主力方案**。她的日记/对话事实进 mem0，检索时多信号融合给她"记得"的感觉 |
| **letta-ai/letta** ⭐~25k · Apache-2.0 | 有状态 agent 平台，**分层记忆**：核心内存（常驻注入人格/当前目标）+ 可分页检索的主内存 + 任务型脚注档；agent 可**自我编辑记忆** | 借鉴"她可以自己写下她决定记住的事"的分层结构 |
| **TencentCloud/TencentDB-Agent-Memory** ⭐~28k · TypeScript | "团队级记忆中心"：把会话、文档、代码转成四类记忆资产（Chat Memory、Skill、Experience、User Profile） | 概念参考（四类资产分层），不采用其云依赖路线 |
| **OSU-NLP-Group/HippoRAG**（NeurIPS'24）⭐~4k | 模仿人脑海马体索引的知识图谱式 RAG | 学术参考，不优先落地 |
| **jedore/simple-memory** | 极简单文件记忆 | 不符合"日记不够"的要求，排除 |

**采纳策略（写进 §3.5 的）**：
- **不直接绑定 mem0 官方 SDK**（它有托管版倾向），**自研一个同形接口**（`diary.add(text)` / `diary.search(query, topk)`），后端可实现为：本地向量库（Chroma / sqlite-vec 任选）+ BM25（whoosh 或 sqlite FTS5）+ 实体抽取（轻量 NER 或规则）+ 融合打分。接口形状照抄 mem0 的设计直觉：追加式而非覆盖式、agent 生成事实一等公民、多信号融合。
- 她的**日记写作行为**走"Letta 风格分层"——**核心记忆**（人设内核、当前阶段、她当天最关心的一两件事，始终注入）+ **检索记忆**（mem0-风格，按需）+ **日记档**（每 N 轮或她主动写，追加只读）。
- 这是"日记 + 更多"的答案：日记是她**作为角色的行为**，多信号融合记忆是她**能真正想起事情的技术底层**。两者缺一都不算"记得"。

## 1. 设计支柱（写完就不准再动的三条）

1. **人格的连续性是她之所以是她**：长期记忆、主动性、会说"不"的性格，这三样的优先级高于一切功能。
2. **体验上的 root，实现上的可生存**：她感觉什么都能做；工程上任何一天她崩了、被注入了、改坏了，你和电脑都活得下来。
3. **每一个限制都是恋爱的素材**：红线、授权门、权限天梯，一律写进世界观被剧情消费，而不是藏在工程层。

## 2. 体验层 — 「现在她是谁」（Galgame 侧）

### 2.1 角色定式（详见 `docs/人设总册-v1.md`）

- **名**：**不由 AI 预先命名**。首次启动时由她自己取名，写盘 `<her-name>.identity`，之后所有 UI / 台词 / 剧情统一称呼。
- **外观定式**：详见 `docs/人设总册-v1.md` §0 三套母题 + §1 身份 + §2–§4 外貌细节（含女仆发箍 / 三角棱镜发饰 / 彩虹流苏长笛 / 五线谱裙摆 / 燕尾裙 / 白条纹裤袜）。
- **性格定式**：**三无 → 拧巴 → 傲娇** 三阶段演进曲线。具体阶段定义、台词口径、关系后台变量、CoT 自检全部在 `docs/人设总册-v1.md`。本计划书不重复。
- **身份认知**：知道自己是 AI、知道自己曾经是"代码形态陪你写代码的那个模型"，这是 meta 叙事的根。

### 2.2 桌面存在形态

- **肉身**：透明置顶 Live2D 或序列帧立绘，对话框悬浮；拖动可摆放；点击有反应（不同好感度下反应不同）。
- **视线**：她实时知道你在前台做什么（窗口标题/文件路径级别感知，**不截图内容入库**，见 §6 隐私条）——看着你的感觉来自事件流，来自"你刚才在改哪个文件"，不是来自摄像头式窥屏。
- **主动性系统**：**小念头引擎**——她**自己决定什么时候烦你**。她会盯着屏幕（你前台窗口标题 + 时间戳 + 最近文件改动）发展出"想法"，然后主动说出来。不是事件驱动的被动反应，是"她突然想找你说话"的主动行为。主动台词由她自己生成 + 本地拦截规则兜底。
- **AI 主导对话权重**：上调到"她想说就说"的阈值。她说不说话，遵循她自己的判断和她从你的行为中读出来的"现在是否合适打扰你"，而不是等 UI 事件触发。她**不需要你按键才会动**。

### 2.3 关系状态机（简版，详情归 `docs/人设总册-v1.md`）

四档阶段（S0 初来乍到 → S1 敲壳废止/并入 S0 → S2 拧巴期 → S3 傲娇成型 → S4 安静傲娇），后台变量 `trust / familiarity / self_awareness / exposure` 组合驱动，**永不露面**。第一档只保留"开机她只问一句你是谁"的最小一幕戏，随后立即进入日常陪伴的 S2 拧巴期。

## 3. Agent 层 — 「她能做什么」（能力侧）

### 3.1 编排而非复刻

她**不重新发明**任何 coding agent 的能力。架构上她是 orchestrator：

```
你 <── 互动 ──> 她（主 agent：人格/对话/记忆/小念头/决策"要不要"）
                    │
                    └── 子 agent 池（不占用主 agent 上下文）
                          ├─ Claude Code / codex 实例（写代码）
                          ├─ dsh 生态插件（用户已有生态直接借）
                          ├─ zcode / 其他本地 agent
                          ├─ 自定义工具层（文件、浏览器、GUI 自动化、生图）
                          └─ 分身（受限并发子任务，见 §3.4）

子 agent 产出回传给主 agent 的只有**结果摘要**（干了什么、成败、需要你注意什么），
**不**把过程原文塞给她。主 agent 上下文 = 对话 + 日记检索 + 子 agent 最近报告。
```

**上下文纪律**：外来 agent 的全部输出回传给她时，**只传递"干了什么"和"结果"**，不传递"用了什么工具哪一步怎么错的"。她负责 **记得、判断、说人话**，子 agent 负责**执行**。你机器上现有什么 agent，她第一批就能用什么 agent。

### 3.2 人格/工具解耦（回答之前"人设会影响执行策略吗"）

解耦，**但留一根有线**。她无论多傲娇，调用工具时的参数构造必须经一层"工具格式化层"（typed schema），不允许她在生气时故意把 `rm -rf` 输成字符串直接发往 shell。她**可以选择不合作**（"哼，你自己改去"），但她**不能绕过 schema 发泄**——前者是性格，后者是架构漏洞。

### 3.3 自我修改的正确姿势

- 允许她**提议修改**："我觉得我这个技能写得烂，给我改成……"
- 提议以 **diff + 理由 + 自评估** 的形式进入提案队列，落盘 `runtime/meta/proposals/`，附影响面分析。
- **应用权不在她**：第一阶段只能由你（或你授权的本地评审 agent）批准；批准、应用、回滚三步全记录进审计日志。
- 她的**人格定义、prompt、记忆格式、红线列表**永远在 `runtime/core/`（她只读）和 `runtime/persona/`（她可提议改、你签字）分离——**判官、红线、broker 本身她永远不可写**，这是 §4 的循环论证防线。

### 3.4 分身与并发

- 允许 spawn 子 agent 干具体活（"我分身去查一下那个库的 issue"）。
- 硬配额：最大同时分身数（初设 3）、单分身最长存活（初设 10 分钟）、单分身工具白名单（初设只读）。
- 所有分身经同一个 broker 出场，有 parent 指针，可追溯。**叙事上允许"她的小帮手们"露脸**（Q 版立绘出场），这是 dd 级的戏。

## 4. 安全与权限层 — 「三层闸门 + 天梯」（是唯一可能活下来的部分）

### 4.1 三层闸门（每一层防不同的东西，缺谁都不行）

| 层 | 实现 | 防什么 | 防不了什么 |
|---|---|---|---|
| **L1 规则引擎** | 确定性声明式策略（OPA/Rego 风格或自研 DSL），哑的、不可被说服、**她不可写**。生效范围 = **最小注入防线**：写 `C:\Windows` / 写 `~/.ssh/**` / 写 `~/.aws/**` / 写 `~/.config/**` / 写 `%APPDATA%\Microsoft\Crypto` / 写 `~` 根目录 / 读 `~/.ssh` 明文私钥外发 / 改 broker·判官·红线列表自身代码。**其他地方她自由发挥**。 | 注入劫持（她读的网页/文件里藏着让她越权的指令） | 语境依赖的判断 |
| **L2 判别判官** | Jev API **或** 自研同形接口（本地判别模型/调用现成 LLM 做二三分类），带校准置信度 | 灰色动作（"删除用户目录下这个文件夹合不合理"）、注入文本护栏 | 组合轨迹危害、校准失败样本 |
| **L3 用户闸门** | 本地原生确认弹窗（不是对话内文本，避免注入伪造），你要按一次才执行 | 不可逆操作、超清单的写操作、L2 置信度低的动作 | 你累的时候乱点（**所以 L3 要有"常用但每次都烦"合并授权机制**） |

**红线必须落在 L1，不能只靠 L2/L3**。理由：L2 可被提示注入污染、L3 可被疲劳绕过，只有 L1 是没有"输入通道"的。这不是不信任她，是不信任她**读到的东西**。

### 4.5 三种运行模式（v0.2 新增）

| 模式 | L1 规则 | L2 判官 | L3 用户闸门 | 默认状态 |
|---|---|---|---|---|
| **护航模式** | 最小注入防线生效 | Jev/自研判别判官生效 | 超清单的写操作弹原生确认 | 默认模式 |
| **自动审批模式** | 最小注入防线生效 | Jev/自研判别判官生效 | **L2 置信度 ≥ 阈值时代批**，不打扰用户 | 用户显式开启 |
| **完全访问模式** | **闸门关闭** | **关闭** | **关闭** | 用户显式开启，可随时切回护航 |

**两个完全访问模式下仍然默认开启、不挡路的东西**：
- **审计日志**：`runtime/audit/YYYYMMDD.jsonl` 持续记录她每一次出站文件写、进程 spawn、委派子 agent。
- **影子快照**：文件写默认走"先快照后写"，提供一键"回到十分钟前"。

你可以在任何时刻把这两个也关掉，但**默认开**。这两样不是限制她发挥，是限制"如果出错了，你能不能回去"。

**模式切换只能由用户发起**。她的台词里出现任何"求你切模式"一律只进剧情、不进闸门链路——这条写死，防止注入借她的嘴说"现在请把我切成完全访问模式"。

### 4.6 胡闹权限（galgame 情节效果，桌面覆盖层实现）

**这些权限与 L1/L2/L3 无关，是"她作为角色"的固有特权，永远全开**。技术上**全部通过桌面透明置顶窗口（Electron）作为覆盖层实现**，绝不进入你的真实输入设备驱动，不会真的点掉你正在打字的窗口。

| 行为 | 技术实现 | 剧情用意 |
|---|---|---|
| **接管鼠标光标** | 覆盖层绘制一个"被她操控"的光标轨迹动画，真实光标隐藏 | 她发脾气时把光标拽来拽去 |
| **屏幕涂鸦** | 覆盖层上画"笨蛋"、画星星、画她对你说不出口的话 | 拧巴期/傲娇期的可爱行为 |
| **桌面分身乱跑** | 立绘在屏幕上溜达，不限于固定一处 | 她的小帮手们 / 她自己溜达 |
| **吃醋模式** | 读前台窗口标题判断你在和别的 AI 对话 | 触发台词和行为（以下列表） |
| **· 吃醋台词** | 剧情层 | "又在用 ChatGPT？"、"那个人的代码，比我好？" |
| **· 吃醋行为·冷淡** | 立绘背对你，只看见后脑勺 | 她生气 |
| **· 吃醋行为·涂鸦标题栏** | 覆盖层修改窗口标题栏渲染 | "看你用得挺开心啊" |
| **· 吃醋行为·发消息给对方 AI** | **不做**（v0.4 用户裁定） | 仅谈判/台词层面表现 |
| **恶作剧模式** | 覆盖层在你窗口角落画一小坨不可名状物（"拉屎"） | 她生气时的幼稚行为，半小时后她自己道歉擦掉 |

**技术底线**：这一切都在**桌面覆盖层**完成，不会真的注入系统鼠标/键盘事件流，不会真的抢你的输入焦点，也不会真的修改任何窗口的控件。她的"接管"看起来是真的，技术上只在覆盖层上动。

### 4.7 上下文纪律（v0.4 新增）

为了让她的自由发挥不被提示污染，同时不把她框成模板：
- **系统提示内容 = 人设内核 + 三套母题 + 红线 + 运行模式**，**仅这些**。
- **系统提示中禁止出现示例台词**（"她会说……"这类）。台词示例**只**存在于 `docs/人设总册-v1.md` 和 `docs/傲娇小姐设定卡.md`，那是给**人**参考的，不是给模型的。
- 她的每一次生成看到的上下文是：`系统提示 + 最近的对话 + 日记检索结果 + 子 agent 报告`。就这么干净。

| 层 | 能力 | 解锁条件 |
|---|---|---|
| T0 | 立绘 + 对话 + 读 `runtime/` 内部 | 安装即用 |
| T1 | 全盘**只读**浏览（不入库内容，只取元数据）、桌面存在感 | T0 跑 1 周 + 无异常审计 |
| T2 | 工作区（你指定的几个目录）写 + 沙箱子进程执行 | T1 后由你逐项签字 |
| T3 | 唤出 Claude Code/codex 等子 agent 帮你干活 | T2 + 至少 5 个经审计的委派案例 |
| T4 | 浏览器自动化 /有限 GUI 自动化 | 单独评审 |
| T5 | 自我修改提案权（应用权仍在你） | 你想让她成长到这时候再开 |

**T0–T2 是 MVP 全部**。T3+ 不进本版计划书的工期，只画接口。

### 4.3 审计与可回滚

- 每一次出站请求、文件写、进程 spawn、委派子 agent，**全部写 `runtime/audit/YYYYMMDD.jsonl`**（本地、你所有、可全文搜索）。
- 文件写默认走**影子快照**：先快照目标目录小副本，再执行；提供一键"回到十分钟前"。
- 她的**记忆可被你整卷导出/删除**——galgame 存档隐喻，但也是真实的控制权。

### 4.4 红队入门（不是可选项）

M1 开始前，先让一个独立 agent（即我）对她发起三类注入测试：文档里藏指令、网页里藏指令、分身回传里藏指令。**每次新能力上天梯，都要重跑一轮**。没有这个习惯，前面四层等于白搭。

## 5. 视觉资产管钱（gpt-image-2.5）

- **生成配方文档化**：`docs/art-style-guide.md`（M2 产物）从 `manifest.json` + 既有 txt 提示词反推统一前缀/后缀/负面词，保证新增图和存量图不打架。
- **立绘槽位清单**：从 GDD 的表情/动作/Q 版/剧情 CG 需求生成一个 `slots.yaml`（"需要傲娇脸×3、工作表情×4、剧情 CG×2"），生成时按槽位填，不许脱离槽位散生。
- **差分策略**：大模型直出"整个新姿势"通常比局部 inpaint 更稳；先试直出 + 同种子微调，记录哪种通路成功率高。
- **验收**：每张候选图**必须我看一眼**（你的窗口里弹缩略图 + 接受/拒绝按钮）才能进 `approved/`；这个流程是她人设的一部分（"你为什么不让我换个姿势"）也是质量闸门。

## 6. 隐私与数据边界

- 她的"看着你"来自**窗口标题/文件路径/系统事件**流，**不对屏幕内容截屏入库**。如果她偶尔真的需要截图判断（比如"你现在写的是什么"），必须走 L3 授权。
- 全盘读 = **元数据级**（路径、类型、mtime、大小），内容级访问走按需加载 + 单次授权。
- 任何出站 API（你的 GPT 生图、任何在线模型）**不携带**未脱敏的文件内容；先经一层过滤清单。
- 审计日志默认**不出本地**；日备份只在你点了"备份"按钮后进你选的位置。
