## 1. 问题

主代理就是陪伴角色本人。它的上下文要装人设、通用守则、记忆、每日档案、眼前的对话。

以前主代理会自己调 `web_search` / `read_webpage` / `recall_day`：
- 一次 `read_webpage` 最多塞进约 6000 字正文；
- 一次 `recall_day` 最多塞进约 6000 字原始聊天；
- 5 轮工具调用下来，主上下文里可能多出一万多字“资料”。

执行代理的汇报以前也是原样进主上下文：`lastResult` 截到 1200 字，聊天里那条 `[执行代理结束]` 消息带全文，`task_status` 每条 1500 字。

主动研究在一次调用里塞多个网页正文，越长越容易漏细节。

## 2. 原则：谁探究，谁消化；主代理只拿梗概

- **执行代理**：动手干活（读写文件、命令、MCP），自己有会话、自动压缩、撤销。只把「梗概」交给主代理，完整汇报留在任务记录里。
- **并行代理（helper，`runtime/core/helpers.ts`）**：替主代理跑腿查资料，最多 4 个同时跑。用的工具有：
  - `web_search` / `read_webpage`
  - `recall_day`（读某天原始聊天）
  - `search_memory`（含已失效的旧事实）

  每个并行代理有自己的上下文、自己的 6 轮工具调用，用完即弃。交回 `{gist ≤300 字, points ≤5×120 字, sources ≤4, gaps}`，来源只能是它真的搜到或读过的网址。
- **主代理**：不再直接调用这些工具，只有两个委派工具：
  - `ask_helpers({tasks:[{goal}]})`：一次派最多 4 个，并行返回梗概；
  - `open_brief(id)`：梗概不够时再看完整要点。

  定时、设置、任务控制这类输出很小的工具，主代理仍然直接用。
- **主动研究**：每个研究角度派一个并行代理去读网页，再由一个汇总员根据各角度的要点写笔记。汇总员看不到网页原文；两个以上不同网站互相印证，可信度才高。

## 3. 主代理上下文的分层

| 层 | 内容 | 预算 / 规则 |
|---|---|---|
| L0 固定 | 角色卡、通用守则、协议 | 不变 |
| L1 状态 | 身份、心情、陪伴模式、观察、时间 | 小 |
| L2 记忆 | 检索到的记忆（≤2500 token）、核心记忆、每日档案摘要、整体印象、旧日记、可见历史（≤1500 token） | 原有预算 |
| **L3 工作集（新）** | `recentBriefs`：近 3 小时内最多 3 条助手梗概（每条 ≤160 字）。同一件事接着问时不用再派人。<br>`board`：长任务看板，最多 5 行，每行一句：在跑的执行任务及已跑分钟数、在查的助手数、主动研究的状态与最新一条笔记。<br>`researchNotes`：最多 3 条研究笔记的一句话版本 | 合计约 1000 字以内 |
| L4 按需 | 完整梗概（`open_brief`）、某天原话、网页正文、任务完整汇报 | 只在 helper 上下文或界面里，不进主上下文 |

规则：**长程任务把过程写进自己的账本，主上下文只放一句话状态和最后的梗概。**

| 长程任务 | 自己的账本 | 进主上下文的 |
|---|---|---|
| 执行任务 | 执行会话 + `task-run` 记录 | `board` 一行（进行中）→ 结束后 `lastResult.summary` = 梗概（≤400 字），聊天里那条消息也只放梗概并注明“完整汇报在「任务」页” |
| 并行代理 | `briefs`（本机最多 120 份） | `ask_helpers` 的返回值，之后是 `recentBriefs` |
| 主动研究 | `research` 账本（兴趣、笔记、运行记录） | `board` 一行 + `researchNotes` 三句 |
| 每日档案 / 日记 | 档案与日记表 | 原有的摘要与候选 |

## 4. 记忆窗口和长程任务怎么相处

1. **不抢窗口**：长程任务无论跑多久、读多少网页，主上下文里永远只有看板的一行。主代理照常陪聊，不会因为一个任务越聊越“失忆”。
2. **不污染记忆**：梗概和研究笔记是“TA 查到的资料”，不自动写进长期记忆。只有用户在聊天里真的说起、并被记忆提取认定为关于用户的事实，才进记忆。所以网页上的说法不会被当成“用户的事”。
3. **可以接着问**：近 3 小时的梗概留在工作集里。想看细节用 `open_brief`，不用重查。
4. **会过期**：梗概 3 小时后离开工作集（仍可 `open_brief`），本机最多存 120 份。研究笔记 14 天过期。看板只放正在进行或 12 小时内的事。
5. **并发与优先级**：所有请求都走同一个 20 路并发池。用户在聊天里派的助手用 chat 优先级；研究、汇报压缩用 background 优先级。一轮里的多个工具调用并行执行，每个工具结果最多 8000 字，超出截断。

## 5. 节省了多少（单次查资料，粗估）

- **以前**：搜索结果约 2000 字 + 一个网页约 6000 字，都留在主上下文，后续每轮重复计费。
- **现在**：每个助手的梗概约 300–900 字。一次派 4 个也就约 3600 字，而且下一轮只剩工作集里的 3×160 字。
- **执行汇报**：从最多 1200 字（聊天消息里更是全文）降到 ≤400 字。
