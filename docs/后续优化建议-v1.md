# GalAgent 首版之后的优化建议

2026-10-09。建议来自当前实际代码、原生界面、本地模型与测试结果；没有把 localhost fixture 当成真实 Kimi 效果。

## 先验证已经落地的人物状态

E01–E06、8小时再见、拖动模型反应20分钟冷却、来源事件、心情衰减、四轴关系去重与日上限、小目标真实进度已实现；57项测试、独立隐私 / 检索回归和实际包显隐 / 进度 / 续接通过。相处页显示摆放与札记，不显示内部打分。接下来根据真实会话调节节奏，不先扩剧情或强推S3/S4。

后台恢复已修：同userdata保存来源ID任务，退出重启续接，失败最多三次且有退避；缺向量可补，纠正/删除/恢复改写来源不会提交旧结果。普通archive不迁移待处理任务，仍需注意迁移时间点。

## 优先把相处质量验清楚

Kimi 接入是现在最重要的外部缺口。当前环境没有配置本项目的 API Key，运行包提供「连接」页。接入后先做首遇、普通闲聊、被夸、观点不同、纠正记忆和安静后再见等场景，记录实际延迟与结构输出成功率。判断标准是能否持续像同一个人物、是否自然、有具体相处来由；不按“傲娇词出现几次”计分。

上线后的第一轮调整建议只选一个具体问题，比如“她总是重复同一个转折”或“主动插话太频繁”，保留实际对话证据再修改。不要同时更换模型、人格提示和主动性阈值，以免不知道哪项生效。

## 减少后台请求，保持记忆及时

此前相同长会话协议测试捕获 79 次 chat、77 次事实 / 日记任务、66 次摘要任务。现已修正为增量摘要，同样测试的摘要请求降到 17 次，来源不重复；主对话与事实 / 日记次数保持 79 / 77。这是本地协议 fixture 的请求量对照，不能直接换算真实 Kimi 账单或延迟。

本轮已改为保留最近 12 条原始记录，在通常新增 8 条未摘要的旧记录后增量更新。用户 payload 采用完整 JSON、约 4200 的应用估算预算；超大单条显式标注首尾摘录，不声称保存省略部分。失败、空结果、更正及删除不会错误推进 checkpoint。下一步可把事实抽取与日记分开节奏；保留真实会话同步落盘、来源与取消机制。批量抽取要带逐条 sourceId 并核验原句，不能为了减少调用混淆事实归属。任何后台队列都应显示真实 pending 数量并能在退出时收回。

本轮已经修正：主动 token 额度独立计量，用户聊天 / 后台任务不会耗掉她的主动额度。后续调整不要再把所有 token 混成“是否允许主动开口”。

## 内存与冷加载仍有改进空间

真实记忆测试已实现 45 秒空闲释放，以及流式构建向量缓存；1 万条合成数据库本轮热检索 p95 约 132 ms。运行包里也验证了 native ONNX 与离线模型路径。

初次运行包测得模型加载时所有应用进程工作集合计约 1.1 GiB；更新推理库后的最终包实测约 971 MiB，闲时约 576 MiB。这个版本没有达到最初拟定的 400 / 800 MiB 内存目标。共享页面求和与私有内存口径需要分别列出，不能拿单个 Node 的 66 MiB 回收值代表整应用。

优先方向：实测较小中文 / 多语嵌入器与当前固定样本的召回，按需保留必要索引，不在主窗口一次渲染全部历史记忆。嵌入器更换要版本化向量并重新索引，不能把不同模型的同维向量直接混用。CPU 已限制嵌入两线程；不继续盲目调整 arena / 图优化参数，已有对照没有显示足够工作集收益。

打包只包含 Windows x64 的原生推理文件，移除其他平台二进制；保留离线模型，避免用户第一次运行就因下载失败而失去语义记忆。后续可提供更小的在线下载版，但必须清楚说明其联网依赖。

当前动画隔离对照B/A2各120秒：暂停pet位移动画0.723%，恢复2.004%，GPU是主要差异来源；A1有短命进程缺口，不能称完整因果实验。保留可见人物的默认动画。另已确认chat原生隐藏时renderer仍自认可见且呼吸running，显隐通知本轮已修并通过实际app.asar hide/show验证，只暂停隐藏窗；不能用之前的未完整因果实验断言隐藏chat贡献多少CPU。

## 动画先按角色表达扩充

本版统一了六表情加眨眼帧，用有限位移、呼吸与小幅动作形成桌面存在感。各差分的实体轮廓锚点只相差约 1–2 个原图像素；原生切换和眨眼已检查。透明像素命中也改为 alpha 缓存，不能为了摆放方便让一整个透明矩形挡住桌面。

下一批素材优先做“倾听时轻侧头”“被看穿后移开视线”“安静后回望”三类有叙事用途的姿态，不增加几十张彼此不衔接的散图。每次以同一母版编辑并保留服装、棱镜、K、星空母题；先检查动作切换的锚点与帧时间。

Live2D 可以在当前人物表达被认可后另立资产门：需要合法可改造的模型源、适合该人物的分层图、绑定和真实桌面性能。直接套一个外貌不同的现成模型不符合“保持人物风格”。

## 主动性与成长需要真实体验反馈

第一版以新鲜观察、忙碌 / 全屏 / 锁屏抑制、频率预算为底线。接入真实模型后观察几天：她为什么选择这次开口、你是否愿意回应、她能否记住你偏好的节奏。吃醋只是可关闭的小场景，不应成为每次切应用的提醒。

S3 / S4 的进一步成长适合依据不同类型的真实相处事件，保持心情与长期关系分离，不让反复夸奖、离线时间或隐私设置变成刷分 / 扣分机制。

## 最后再接真实 agent 能力

等陪伴、记忆与退出恢复稳定后，另设一个工作区中的小任务：提出目标、确认范围、由单个执行器完成、回传结果摘要、提供验证和恢复。人物继续说人话，执行过程不灌进她的长期聊天上下文。

之后才考虑更多执行器、Jev 辅助判定或 GUI 操作。权限来自程序与用户，不能来自模型的自信度，也不把 Windows 虚拟桌面称为安全沙箱。

## 规模增长后的局部优化

当前来源事件、关系授予账本与工作任务可恢复，并有去重 / 上限；规模增长后应单独测量后台扫描与关系汇总，不把当前1万条检索样本当完整1万条相处事件压力验收。合适的下一步是增量汇总和必要索引，保持来源与删除传播，避免为速度抹掉相处历史。

## 已测的小型中文嵌入候选

固定20事实/40问题，按各自官方pooling/prefix、q8/CPU2线程、独立进程比较：E5可答Top1 33/35、Top3 35/35，采样峰RSS620.56MiB；Xenova/bge-small-zh-v1.5官方CLS可答Top1 30/35、Top3 34/35，峰172.33MiB，减少约72.2%。BGE冷向量约624ms，query编码p95约5.50ms。

这个数字不含Electron/观察/GPU，不能把172MiB当整个应用内存。尚未更换当前E5，也未通过完整迁移门。进入下一验证需要：固定独立中英名称/历史/未知样本，实际FTS融合与候选选择，model/revision/pooling/prefix/dtype版本化、来源保留的重新索引、实际包全进程峰/idle。现有E5的0.65余弦阈值不可直接用于BGE；它的正确咖啡样本分数仅约0.53–0.59，不同模型分数不是可互换置信度。

保留当前包及持续观察，不因一个较低RSS牺牲已验证人物与记忆效果。完整证据在chinese-embedding-candidate.json及配套说明。

最终包十分钟无模型静置CPU平均1.416%，2%这一样本门已通过；不能用先前约3%的旧版本均值作为当前结论，也不能宣称所有负载通过。

### 候选后续结论与已完成的索引修复

独立中英holdout实际融合门曾让E5/BGE分别只有36/48、35/48；定位为英文字符FTS弱匹配。已仅修关键词索引边界，保持E5/RRF/阈值，E5提升48/48（中26/26、英22/22），历史及删除隔离通过；旧库重建保留事实/向量并可回滚。BGE复测41/48、英文15/22，未达到目标，不迁移、不以低RSS替代召回。61项测试和独立Windows修正版协议通过。停止这轮试模，先做真实人物验收；内存预算仍须如实保留缺口。

## 透明动态桌宠形体 v2 的下一步

本轮按用户纠正以角色为主：二维网格、局部眼/嘴层、不同身体部位滞后与贴身短输入已制作，固定页只作辅助。先让用户评价默认尺寸下的动作幅度和看向鼠标的节奏。下一次美术投入优先独立发/眼/口/手臂层，而不是更多完整静态立绘；丰富转身/挥手需要专属分层与Live2D rig。文字口动目前不是音频同步。真实模型和完整真机长时测试按本轮要求放缓；原内存预算未重新验收，不能拿17ms可见样本覆盖所有状态。
