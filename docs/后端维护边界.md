# GalAgent 后端维护边界

本文对应 v0.99.0 本地后端维护版。对外入口是 Electron IPC、共享的 AppCommand / AppSnapshot，以及执行器的工具协议。内部模块可以重组；存档格式、应用密钥的保护方式、主动开口门控和用户设置均有已有调用方。

## 按改动找到代码

## 设置、主动开口与执行器工具轮次

- 设置补丁先由 settings.ts 校验，再由 settings-effects.ts 比较前后值。CompanionService.updateSettings 落实取消任务、更新策略版本、清缓冲、撤回注意力判断和恢复评估。桌面设置、已授权的 AI 调整、一键隐私和休息切换共用这条处理路径。
- initiative-policy.ts 负责主动开口的安静时段、模式、频率和本地空闲判定。用户亲自设置的提醒可以在专注模式下响，休息、临时安静和免打扰仍生效。注意力决定开口前登记当次尝试，用户无需逐次点击。
- openai-agent.ts 管会话、模型请求、压缩、预算和取消；executor-tool-batch.ts 管一轮工具的整批预检、只读并行、含写操作的串行执行，以及按调用 ID 回填结果。

## 主动研究与分享后的对话

CompanionService 提供授权范围内的观察、记忆和状态。research-runner.ts 负责一次研究从准备到完成的生命周期；并发触发共用同一个在途位置，暂停或移除兴趣会中止请求。research.ts 管兴趣账本、去重、反馈、休息期与来源选择。research-preference.ts 只从用户直接提出的简短关注请求调整兴趣。

研究助手只有实际读取到正文的网页才能成为新发现的来源。分享时最多给角色一条笔记，附上站点和缘由；如果有关联的有效记忆，再到原始用户消息核对文字。兴趣来自观察而非用户原话时，提示词区分推测和事实。刚结束对话先给用户五分钟空档；明确关注的可靠新进展可以在下一个合适时机分享，个人节奏、免打扰及每日上限照常生效。用户追问刚才的来源时，短期话题记录提供已分享的原文网址；该记录随研究账本保存在本机。

## 工具总入口

ToolHost.execute 统一检查信号、参数、会话模式，再分派。executor-session-tools.ts 登记待办、目标、计划、问题、任务控制和定时工具；文件、媒体、Shell、联网、助手及 MCP 仍从相同检查入口进入。后台提问跟随父任务取消；迟到的回答不能将已取消的任务重新标为完成。

## 保留在主服务中的工作

CompanionService 持有活动角色、当前生成、主动门控、取消和快照发布。命令可能同时改变几项状态。例如切换为休息模式需要使注意力判断失效、取消主动生成、清除观察缓存并发布新快照。设置模块只返回新设置，主服务统一执行这些副作用。

存档导入也分两步。校验模块只读本地记录，检查身份、来源、故事与变量之间的引用；主服务在校验通过后进入 SQLite 事务。日常恢复仍走同一入口。

### 后台作业的提交顺序

作业用种类和来源生成固定 ID，重复唤醒共用同一个排队位置。调度器持有在途任务的取消信号；关闭时先停计时器并取消作业，再等队列清空，最后关闭 SQLite。业务处理器等模型或向量结果返回后，要重新检查来源和任务是否仍有效，再把结果和完成标记一起写入事务。来源内容变了就延后重做；来源被删除就丢弃结果。日记沿用按日期生成的 ID，重试覆盖同一条记录。

## 执行任务和文件撤销

runtime/core/task-supervisor.ts 持有每个任务的会话归属、取消信号、子进程和退出状态。停止会话会处理本会话与其子会话的任务，独立会话继续运行。权限策略更新和应用关闭仍由 ToolHost 发起全局取消。

runtime/core/file-checkpoints.ts 保存每次执行中的文件初始内容和写后指纹。有检查点的文件修改和撤销进入同一写入队列，清单以临时文件替换。撤销前重新检查路径策略并比对写后指纹；文件已经被用户改动，或者没有可确认的写后指纹时，保留文件并向调用方报告冲突。模型请求和 Shell 进程独立于这条文件写入队列。

维护一条功能时，从现有公开入口运行回归。类型检查与单元测试完成后，改动涉及进程接线、密钥或打包依赖时，再运行 windows-release 和 dual-core 两个打包验收脚本。两者均支持 GALAGENT_TEST_EXE 指定同一个 exe。Windows 验收使用临时存档及本机模拟模型。

主动研究的专项 Windows 验收使用 tests/e2e/research-companion.mjs，临时存档、预置研究笔记和本地模拟模型，覆盖正常心跳分享、重启追问来源和暂停置顶兴趣。


## 任务完成后的可选摘要

执行器返回的状态、全文历史、本地摘要和完成事件先同步写入并发布。模型压缩仅作后台改进，一次最多保留一个请求；用户取消、清空历史或关闭程序会撤回请求。返回后检查原任务与消息是否仍存在，只更新原消息，并且只有该任务仍是最近结果时才更新 lastResult。waitForAgent 只等待执行任务完成。摘要不能产生第二条 task 事件。

关机先发出取消信号，再等待执行会话；摘要等待使用可中断的包装，即使测试上游不响应取消，迟到结果也无法访问已经关闭的数据库。

## 持续跟进与开口时机

care-events.ts 从主角色回复中的 careUpdates 接收事件更新。只接受本轮用户原话里能找到的证据；创建事项、改期、结束和暂停共用事项 ID。日期由本地代码按用户时间原话推算，明确时刻之后留出时间，只有日期时在该日结束后再问。模糊时间保留原话，后续问安排，不能假定已发生。每个版本的事项只主动发言一次，改期会更新下次时机。来源被删或被替换时，该事项及相关私有对话依赖失效。

当前事项和最近结果进入主角色上下文，关心消息仍受模式、安静、话题、频率和在场条件约束。全屏、刚切换窗口、刚说过话或尚未回应上一次主动消息时，普通关心延后；任务结果和明确提醒走其既有门控。自适应回应只针对最近一条待回应的主动消息。

## 后台请求与直连接口

一轮研究的多个助手共享相同搜索和网页读取的 Promise；新一轮重新读取。研究材料准备好后遇到用户正在聊天，会等待再请求综合模型。全局并发池继续优先处理聊天。

api-response.ts 限制响应读取大小，取消可打断连接等待和正文等待，错误信息隐藏当前密钥并给出 HTTP 状态。模型明确拒绝 JSON 模式时，主代理按端点与模型记忆兼容方式，保留仍可用的工具；执行器支持对不接受的 stream_options 与输出 token 参数做有界回退。主代理可读取普通 JSON 或完整 SSE 回复。

## 存档位置与保存

main/profile.ts 在 Electron 就绪前选择存档：显式 --profile-directory、GALAGENT_DATA_DIR、用户已记住的目录、默认应用数据目录依次优先。只有显式 --remember-profile 才更新独立选择文件；测试环境变量不改变日常选择。已记住的位置缺失时停止启动，避免误开旧数据。userData 与 sessionData 使用同一选定目录。

Store.saveState 将相关状态作为一次事务提交，已有事务中不再嵌套开启；SQLite 使用 WAL 与 FULL 同步。companion 的持久化入口写入保存时间，快照向界面暴露目录和时间。profile-save.mjs 在隔离目录验证进程被强制结束后仍恢复原聊天、记忆、设置与身份。
